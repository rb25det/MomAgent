**文書番号**: MomAgent-REQ-001  
**バージョン**: 1.0  
**作成日**: 2026年1月7日  
**作成者**: 開発チーム

---

## 1. はじめに

### 1.1 目的
本書は、「お母さんAI（MomAgent）」システムの要件を定義するものである。本システムは、ユーザーに対して日本のお母さんのような温かく寄り添う対話体験を提供し、予定管理のサポートを行うことを目的とする。

### 1.2 対象読者
- システム開発者
- プロジェクト管理者
- 品質保証担当者
- 運用担当者

### 1.3 用語定義

| 用語 | 定義 |
|------|------|
| LLM | Large Language Model（大規模言語モデル） |
| Ollama | ローカル環境でLLMを実行するためのプラットフォーム |
| セッション | ユーザーがブラウザを開いてから閉じるまでの一連の対話 |
| チェッカー | LLM応答を検証するサブシステム |
| 終了判定 | ユーザーが会話を終わらせたいかを検出する機能 |
| Nudge（ナッジ） | 会話終了時に次の話題や予定を提案する機能 |

## 2. システム概要

### 2.1 システムの位置づけ
本システムは、一人暮らしの学生や社会人が日常的に利用することを想定した対話型AIアシスタントである。従来のAIアシスタントとは異なり、「お母さん」という親しみやすいペルソナを持ち、単なる情報提供ではなく、ユーザーの感情に寄り添った対話を重視する。

## 3. 機能要件

### 3.1 ユーザー管理機能

#### FR-001: プロフィール登録
| 項目 | 内容 |
|------|------|
| 概要 | ユーザーの基本情報を登録する |
| 入力 | ニックネーム、性別、年齢、学年/役職、生活リズム、健康情報、関心事項 |
| 処理 | 入力データを検証し、セッションに保存する |
| 出力 | お母さん設定画面への遷移 |
| 優先度 | 必須 |

#### FR-002: お母さん性格設定
| 項目 | 内容 |
|------|------|
| 概要 | AIの性格パラメータを設定する |
| 入力 | 厳しさ/優しさ、寡黙/おしゃべり、方言、対話スタイル |
| 処理 | 設定を基にカスタムLLMモデルを生成する |
| 出力 | チャット画面への遷移 |
| 優先度 | 必須 |

### 3.2 対話機能

#### FR-003: 自然言語対話
| 項目 | 内容 |
|------|------|
| 概要 | ユーザーと自然な日本語で対話する |
| 入力 | ユーザーのテキストメッセージ |
| 処理 | 会話履歴を含めてLLMに問い合わせ、応答を生成 |
| 出力 | お母さんらしい応答テキスト |
| 優先度 | 必須 |

#### FR-004: 文脈維持
| 項目 | 内容 |
|------|------|
| 概要 | 会話の文脈を維持し、一貫した対話を提供する |
| 入力 | 過去の会話履歴（最新30件） |
| 処理 | 直近の会話内容を参照し、文脈に沿った応答を生成 |
| 出力 | 文脈を維持した応答 |
| 優先度 | 必須 |

#### FR-005: 応答品質チェック
| 項目 | 内容 |
|------|------|
| 概要 | LLM応答の品質を検証し、必要に応じて再生成する |
| 入力 | 候補応答、会話履歴、ユーザープロフィール |
| 処理 | 文脈整合性、トーン、繰り返し、不適切表現を検証 |
| 出力 | 検証済み応答（または再生成後の応答） |
| 優先度 | 高 |

#### FR-006: 会話終了検出
| 項目 | 内容 |
|------|------|
| 概要 | ユーザーが会話を終わらせようとしているかを検出する |
| 入力 | ユーザーの最新発言、会話履歴 |
| 処理 | 別れ表現、感謝、短い同意/決意を検出 |
| 出力 | 終了判定結果（ending: true/false, confidence: 0.0-1.0） |
| 優先度 | 高 |

#### FR-007: 予定リマインドナッジ
| 項目 | 内容 |
|------|------|
| 概要 | 会話終了時に登録済み予定を自然に提案する |
| 入力 | 登録済み予定一覧、既にナッジ済みの予定リスト |
| 処理 | 未ナッジの予定から日時順に選択し、応答末尾に追加 |
| 出力 | 予定を含む応答テキスト |
| 優先度 | 中 |

### 3.3 予定管理機能

#### FR-008: スケジュール意図分類
| 項目 | 内容 |
|------|------|
| 概要 | ユーザー発言が予定に関する質問かを判定する |
| 入力 | ユーザーメッセージ |
| 処理 | クイックフィルター（正規表現）→ 必要に応じてLLM判定 |
| 出力 | 意図（schedule_query/not_schedule）、スコープ、信頼度 |
| 優先度 | 必須 |

#### FR-009: 予定登録
| 項目 | 内容 |
|------|------|
| 概要 | 新しい予定を登録する |
| 入力 | 日付、時間、内容、場所、優先度 |
| 処理 | 入力を検証し、セッションに保存 |
| 出力 | 予定一覧画面への遷移 |
| 優先度 | 必須 |

#### FR-010: 予定一覧表示
| 項目 | 内容 |
|------|------|
| 概要 | 登録済み予定を一覧表示する |
| 入力 | なし |
| 処理 | セッションから予定を取得し、日時順にソート |
| 出力 | 予定一覧HTML |
| 優先度 | 必須 |

#### FR-011: 予定編集・削除
| 項目 | 内容 |
|------|------|
| 概要 | 既存の予定を編集または削除する |
| 入力 | 予定ID、編集内容または削除指示 |
| 処理 | セッション内の予定データを更新/削除 |
| 出力 | 更新後の予定一覧 |
| 優先度 | 必須 |

#### FR-012: 予定問い合わせ応答
| 項目 | 内容 |
|------|------|
| 概要 | 予定に関する質問に対して登録済み予定を回答する |
| 入力 | スコープ（today/tomorrow/week/month/next/upcoming） |
| 処理 | スコープに応じた日付範囲で予定をフィルタリング |
| 出力 | 該当予定のリスト（お母さん口調） |
| 優先度 | 必須 |

### 3.4 ログ機能

#### FR-013: 会話ログ保存
| 項目 | 内容 |
|------|------|
| 概要 | 全会話内容をセッション別ファイルに保存する |
| 入力 | ユーザー/AIの各発言 |
| 処理 | タイムスタンプ付きでテキストファイルに追記 |
| 出力 | `logs/chat_{timestamp}_{session_id}.txt` |
| 優先度 | 必須 |

#### FR-014: 分類器イベントログ
| 項目 | 内容 |
|------|------|
| 概要 | スケジュール意図分類の結果をログに記録する |
| 入力 | 分類結果、処理時間、エラー情報 |
| 処理 | JSONL形式でファイルに追記 |
| 出力 | `logs/classifier_events.log` |
| 優先度 | 高 |

#### FR-015: チェッカーイベントログ
| 項目 | 内容 |
|------|------|
| 概要 | 応答チェック結果と再生成イベントを記録する |
| 入力 | チェック結果、再生成前後の応答 |
| 処理 | JSONL形式でファイルに追記 |
| 出力 | `logs/checker_events.log` |
| 優先度 | 高 |

#### FR-016: 終了検出イベントログ
| 項目 | 内容 |
|------|------|
| 概要 | 会話終了検出の結果を記録する |
| 入力 | 検出結果、信頼度、判定理由 |
| 処理 | JSONL形式でファイルに追記 |
| 出力 | `logs/end_detector_events.log` |
| 優先度 | 高 |

## 4. 非機能要件

### 4.1 性能要件

| ID | 要件 | 目標値 |
|----|------|--------|
| NFR-001 | 応答時間（通常会話） | 15秒以内 |
| NFR-002 | 応答時間（予定問い合わせ） | 5秒以内 |
| NFR-003 | チェッカー処理時間 | 8秒以内 |
| NFR-004 | 終了検出処理時間 | 4秒以内 |
| NFR-005 | 同時接続ユーザー数 | 1ユーザー（ローカル想定） |

### 4.2 信頼性要件

| ID | 要件 | 内容 |
|----|------|------|
| NFR-006 | LLMタイムアウト時のフェイルオーバー | タイムアウト時はエラーメッセージを返却 |
| NFR-007 | チェッカー失敗時のフェイルオーバー | 解析失敗時はデフォルトで応答を受け入れる |
| NFR-008 | セッション永続性 | サーバー再起動時はセッション情報を喪失（許容） |

### 4.3 セキュリティ要件

| ID | 要件 | 内容 |
|----|------|------|
| NFR-009 | 個人情報の保護 | プロフィール情報はセッション内のみ保持 |
| NFR-010 | ログへの機微情報記録 | 会話ログは開発用途のみ、本番運用時は設定で無効化可能 |
| NFR-011 | 外部通信 | Ollama API（localhost）のみ、外部インターネット通信なし |

### 4.4 運用要件

| ID | 要件 | 内容 |
|----|------|------|
| NFR-012 | 設定変更 | `config/settings.json`の編集で主要パラメータ変更可能 |
| NFR-013 | 環境変数オーバーライド | 環境変数で設定値を上書き可能 |
| NFR-014 | ログローテーション | セッションごとに新規ログファイル生成 |

### 4.5 保守性要件

| ID | 要件 | 内容 |
|----|------|------|
| NFR-015 | モジュール分離 | 分類器、チェッカー、終了検出器を独立モジュール化 |
| NFR-016 | プロンプト管理 | システムプロンプトはテキストファイルで管理 |
| NFR-017 | コード可読性 | 日本語コメント付き、関数単位で責務を分離 |

## 5. 制約事項

### 5.1 技術的制約
- **LLM実行環境**: Ollamaがローカルにインストールされていること
- **ベースモデル**: ELYZA-japanese-Llama-2-7b-fast-instruct相当のモデルが利用可能であること
- **Python環境**: Python 3.10以上
- **ネットワーク**: localhost（127.0.0.1）でのOllama API通信

### 5.2 運用上の制約
- 本システムは単一ユーザーのローカル利用を想定
- マルチユーザー環境での利用は想定外
- 予定データは永続化されない（セッションベース）

## 6. 将来の拡張性

### 6.1 検討中の機能
- 予定データのデータベース永続化
- 複数ユーザー対応
- 音声入出力対応
- モバイルアプリ化
- 外部カレンダー連携（Google Calendar等）

### 6.2 アーキテクチャ上の考慮
- 分類器・チェッカー・終了検出器は独立モジュールとして設計済み
- 設定の外部化により、パラメータ調整が容易
- プロンプトのテンプレート化により、ペルソナ変更が可能
