# 予定補完機能 要件定義（詳細版）

## 目的
- 予定は既存のUI（予定追加/編集フォーム）で登録する。
- 会話は「未入力項目の補完」と「お母さんとしての確認・促し」に特化する。
- 補完された情報は既存予定に付加し、整合性を保つ。
- 補完の対象項目は固定せず、「お母さんの性格設定」で制御できるようにする。

## 現状の前提
- 予定は `session["schedules"]` に保存される（永続化なし）。
- 予定の必須入力は `date`, `time`, `content`。
- 任意入力は `priority`, `remind_value`, `remind_unit`。
- 予定の追加/編集は UI で完結しており、会話は別経路。

## 拡張後の予定データ（保存対象）
- 既存項目（変更なし）
  - `date`, `time`, `content`, `priority`, `remind_value`, `remind_unit`, `created_at`
- 追加項目（補完対象として拡張）
  - `deadline`（締切日/期限）
  - `duration_minutes`（所要時間）
  - `location`（場所）
  - `notes`（備考/準備物）
- 将来的な追加に耐えるため、補完項目はリスト定義で管理する。

## 補完の基本方針
- UI登録済みの予定に未入力項目がある場合、会話で順番に質問して補完する。
- 補完内容は該当する予定に上書き保存し、一覧/編集にも反映する。
- 補完は「お母さんの性格設定」に従って聞く項目を変えられる。

## 補完対象の制御（お母さん性格設定との連動）
- `mom_settings` に補完方針を追加する想定。
- 例: `schedule_completion_fields` に「聞きたい項目一覧」を持たせる。
- 項目の選択は UI のチェックボックスで制御（例: 締切/所要時間/場所/リマインド）。
- ここで指定されていない項目は、未入力でも会話では聞かない。

## 補完の対象判定（整合性）
- 判定条件は「指定された補完対象項目が未入力であること」。
- 未入力判定の例
  - `remind_value` が空 or 未設定
  - `deadline` が空
  - `duration_minutes` が空
  - `location` が空
- 判定は予定ごとに行い、複数未入力がある場合は順番に聞く。

## 会話フロー要件
- 予定追加/編集後の次の会話で補完を開始する（未入力がある場合のみ）。
- 会話中は「補完モード」を維持し、1項目ずつ質問する。
- 回答が曖昧な場合は再質問する（例: 日付や時間が曖昧など）。
- 補完完了時は必ずまとめて確認し、同意が取れたら保存。

## 会話パターン例（お母さん口調）
- 確認開始: 「さっき入れた予定、ちょっと聞いてええ？」
- 不足情報の質問: 「場所はどこやっけ？」
- 所要時間の確認: 「どれくらいかかりそう？」
- 締切の確認: 「それ、いつまでに終わらせたい？」
- まとめ確認: 「じゃあ、○月○日○時で、場所は△△、所要時間は□分で合ってる？」

## 状態管理要件
- セッションに「補完中の予定ID」と「次に聞く項目」を保持する。
- 例: `session["schedule_completion"] = {"index": 2, "pending_fields": ["location", "deadline"]}`
- 補完完了時は `schedule_completion` をクリア。

## UI 反映
- 補完結果は `session["schedules"]` の対象予定に即時反映。
- 予定一覧と編集画面で補完済み内容が表示される。

## 非機能要件
- 既存の予定追加/編集フローを壊さない。
- 補完対象が空の場合は補完モードを起動しない。
- 補完中にユーザーが「やっぱりやめる」と言った場合は中断できる。

## 受け入れ条件（例）
- 予定に `location` が未入力で、補完対象に設定されている場合、会話で場所を聞く。
- 回答後、予定一覧に `location` が反映される。
- `schedule_completion_fields` に含まれない項目は未入力でも聞かれない。
- 補完完了後、会話が通常モードに戻る。
