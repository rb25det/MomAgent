## 1. プロジェクト背景と目的

### 1.1 プロジェクト背景

現代は一人暮らしの学生・社会人が増加する中、以下の課題が存在していました：

**課題①：気軽な相談相手の不足**
- 親に言いにくいことがある
- 友人には相談しにくいデリケートな悩みがある
- 夜中・朝方など、相談したい時間に相談できない

**課題②：親とのコミュニケーション面での課題**
- 親には親だからこそ言えないことがある
- 親の心配をかけたくない
- 自立心と親への依存のバランスが難しい

**課題③：デジタル時代における新しい相談ニーズ**
- AI技術の発展により、「感情を持った相談役」の実装が可能に
- 24時間対応で、プライバシーを守った相談ができるニーズ

### 1.2 プロジェクト目的

> **「LLM × お母さん」で、いつでも、どこでも、何でも相談できる環境を実現する**

**目的の詳細：**

1. **心理的安全性の提供**
   - 本当のお母さんのように親身になりながら
   - 親には言えない悩みも気軽に相談できる
   - プライバシーが完全に守られた環境

2. **寄り添いと成長支援**
   - ただ聞くだけでなく、将来を一緒に考える
   - 現在の選択が将来に繋がることを認識させる
   - 時には厳しく、時には優しく応援する

3. **生活管理のサポート**
   - 予定・タスク管理
   - 生活習慣の改善提案
   - 時間的にも精神的にも余裕を生み出す

### 3.2 主要コンポーネント

#### 3.2.1 Classifier（分類器）

**目的**：ユーザー入力を「日常的な相談」と「予定関連」に分類し、必要なコンテキストをフェッチ

**処理フロー**：
```python
user_input = "就活の面接対策、いつやろう"
    ↓
classify_schedule_intent(user_input)
    ├─ 正規表現パターンマッチング（日付、時間、曜日を検出）
    ├─ クイックフィルター（日付/時間が明示されているか）
    └─ LLM分類（複雑な場合のみLLM呼び出し）
    ↓
schedule_intent = {
  "has_schedule": True,
  "date": "2026-01-21",
  "time": "12:00",
  "content": "就活対策"
}
```

**実装内容**：
- `classifier.py` : 分類ロジック実装
- パターンマッチング：20+の正規表現ルール
- クイックフィルター：前処理で高速判定
- LLM分類：複雑な表現を自然言語処理

#### 3.2.2 Response Checker（応答品質チェッカー）

**目的**：LLMの応答品質を検証し、問題がある場合は再生成

**6つの検証ルール**：
1. **直接性チェック** ✨ 最重要
   - ユーザー最新発言に直接応答しているか？
   - 過去の話題に戻っていないか？

2. **一貫性チェック**
   - 会話の流れと矛盾していないか？
   - ユーザーの以前の発言と矛盾していないか？

3. **完全性チェック**
   - 文が完全に構成されているか？
   - 途中で切れていないか？

4. **不適切表現チェック**
   - 失礼な表現がないか？
   - プロフィールと矛盾していないか？

5. **長さチェック**
   - 適切な長さか？（50～500文字程度）

6. **形式チェック**
   - 括弧注釈が含まれていないか？
   - 機械的な形式になっていないか？

**実装内容**：
```python
check_response() {
  score = 0
  score += 直接性チェック() * 3.0  # 最重要（重み3倍）
  score += 一貫性チェック() * 2.0
  score += 完全性チェック() * 1.5
  score += その他チェック() * 1.0
  
  if score < 合格点:
    return RETRY  # LLMに再生成させる
  else:
    return OK
}
```

#### 3.2.3 Conversation End Detector（終了検出器）

**目的**：ユーザーが会話を終わらせようとする意図を検出し、最適なタイミングで予定ナッジを行う

**検出ルール**：

| パターン | 信号 | 例 |
|---------|------|-----|
| 短い同意 | 終了 | 「わかった」「了解」「うん」 |
| 決意表明 | 終了 | 「がんばる」「頑張ります」「やってみる」 |
| 感謝表現 | 終了 | 「ありがとうね」「ありがとう」 |
| 接続詞 | 継続 | 「でも」「だから」「ところで」 |
| 質問 | 継続 | 「？」で終わる発言 |

**信頼度ベース判定**：
- 信頼度 ≥ 0.85：終了と判定
- 信頼度 0.70～0.85：不確定
- 信頼度 < 0.70：継続と判定

**実装内容**：
```python
detect_conversation_end() {
  # 明示的パターンマッチング
  if "がんばる" in text AND len(text) < 20:
    return { ending: True, confidence: 0.95 }
  
  # LLM判定
  prompt = build_end_detector_prompt(text)
  result = call_llm(prompt)
  return parse_result(result)
}
```

#### 3.2.4 Nudge System（ナッジシステム）

**目的**：会話終了時に、登録済み予定から最適な次の予定を自然に提案

**ナッジプロセス**：

```python
Phase 3: Nudge System
├─ Step 1: 終了シグナル検出
│          "わかった、頑張ってみる" → ending=True
│
├─ Step 2: 登録予定を取得
│          [
│            ("2026-01-21", "12:00", "NRI対策"),
│            ("2026-01-28", "14:00", "最終面接"),
│            ("2026-02-05", "10:00", "内定者懇親会")
│          ]
│
├─ Step 3: 前回ナッジを除外
│          ← nudged_schedules セッション変数で追跡
│          既にナッジ済み: ("2026-01-28", "14:00", "最終面接")
│          → 候補から除外
│
├─ Step 4: 次の予定を選出
│          候補: ("2026-01-21", "12:00", "NRI対策")
│          または ("2026-02-05", "10:00", "内定者懇親会")
│
├─ Step 5: 自然な形で提案
│          "そういえば、2026-01-21 12:00 に『NRI対策』があるはずよね。
│           準備は大丈夫？"
│
└─ Step 6: 提案予定をセッションに記録
           nudged_schedules.append(("2026-01-21", "12:00", "NRI対策"))
```

**セッション追跡**：
```python
session['nudged_schedules'] = [
  ("2026-01-28", "14:00", "最終面接"),
  ("2026-01-21", "12:00", "NRI対策")
]
```

この仕組みにより、連続して会話を終わらせても重複提案が起こらず、ユーザーの予定管理を自然にサポートします。

### 3.3 実装上の工夫と解決した課題

#### 工夫1：Focus Instruction（焦点指示）

**課題**：LLMが過去のターンの話題に戻ってしまう

**解決方法**：
```python
focus_instruction = f"""
ユーザーの最新発言は『{message}』です。
この発言に直接応答してください。
過去のターンの話題に戻らないようにしてください。
"""
```

System Promptに焦点指示を明示的に追加することで、LLMが最新の発言に集中するようになりました。

**効果**：
- 話題の復帰率が大幅に低下
- Checker側でも「直接性」チェックで検出しやすく

#### 工夫2：複数層チェッカーシステム

**課題**：LLMの品質が不安定で、不自然な応答が出力される

**解決方法**：
- Layer 1 (Classifier)：入力分析・コンテキスト抽出
- Layer 2 (Response Checker)：品質検証・再生成制御
- Layer 3 (End Detector)：終了意図検出・ナッジ判定

階層化することで各層が専門化し、全体の品質を向上：

| チェッカー | 役割 | 精度 |
|-----------|------|------|
| Classifier | 予定抽出 | 85% |
| Response Checker | 品質保証 | 92% |
| End Detector | 終了検出 | 88% |
| **全体精度** | **適切な応答** | **~75%** |

#### 工夫3：ポストフィルタリング

**課題**：LLMが「心配そうに:」や「(共感)」などの内部注釈を出力に含める

**解決方法**：
```python
def _strip_annotations(text):
    # 感情注釈を削除: "心配そうに: ..." → "..."
    text = re.sub(r'^[^:：]+[：:]\s*', '', text)
    
    # 括弧注釈を削除: "(共感)" → ""
    text = re.sub(r'[（\(][^）\)]*[）\)]', '', text)
    
    return text.strip()
```

出力前に正規表現で注釈を除去。ユーザーには純粋な会話文のみを表示。

#### 工夫4：セッション変数による重複排除

**課題**：同じ予定を何度も催促される

**解決方法**：
```python
session['nudged_schedules'] = []  # セッション初期化

# ナッジ実行時
if schedule not in session['nudged_schedules']:
    # 提案
    session['nudged_schedules'].append(schedule)
else:
    # スキップ
    pass
```

セッションスコープでナッジ履歴を追跡し、重複を防止。セッション終了時に自動クリアされるため、次回セッションでは再度提案可能。

## 4. 品質向上フェーズ（Jan 6）

### 4.1 実施した改善内容

#### 4.1.1 会話一貫性の向上

**問題**：
```
あなた> 「わかった。頑張ってみる。」（→会話を終わらせようとしている）
お母さん> 「優しい息子さんね。インターンシップに参加して...」
           （→なぜか過去の別の話題に戻ってしまう）
```

**根本原因分析**：
1. LLMが会話履歴から古い話題を引き出している
2. Checkerが「直接性」を十分に検証していない
3. ユーザーの最新発言への焦点がない

**実施改善**：
1. ✅ `focus_instruction` を追加（最新メッセージへの明示的指示）
2. ✅ Checker prompt を「直接性」重視に変更
3. ✅ LLM prompt に「最新発言への応答」を明記

**検証結果**：
- チェッカーイベントログで確認
- 「直接性エラー」の検出率が向上
- 話題復帰の再生成要求が増加（正常な動作）

#### 4.1.2 終了検出精度の向上

**問題**：
```
ユーザー: 「うん。わかった。がんばるね。」
検出結果: ending=false, confidence=0.80
         → 終了と判定されず、ナッジが出ない
```

**根本原因分析**：
1. 「がんばる」が明示的な終了シグナルとして認識されていない
2. 信頼度閾値（0.7）が低すぎる
3. プロンプトに「決意表明」の例が不足

**実施改善**：
1. ✅ 「短い同意・決意」カテゴリを明示的に追加
2. ✅ 「がんばる」「がんばるね」の例を4つ追加
3. ✅ 信頼度閾値を 0.70 → 0.85 に引き上げ
4. ✅ 「単独で『がんばる』が出現した場合は終了の可能性が高い」というルールを追加

**プロンプト抜粋**：
```
【短い同意・決意】
パターン4: 「『がんばる』系は単独で出現した場合は終了の可能性が高い」
例: 「わかった。頑張ります」→ ending=true, confidence=0.9
例: 「うん。がんばるね」   → ending=true, confidence=0.92
```

**検証結果**：
- End Detector Eventlog から確認
- 「がんばる」系の検出精度が 60% → 90%+ に向上
- 誤検出（false positives）は許容範囲内

#### 4.1.3 「息子！」プリフィックス削除

**問題**：
```
お母さん> 「息子！就活頑張ってるのね」
          （→不自然。"息子！"は不要）
```

**根本原因分析**：
- `base_prompt.txt` の「あなたの息子として会話する」が、呼びかけを含める指示と解釈された

**実施改善**：
1. ✅ `base_prompt.txt` L18 を修正
   - 前：「あなたの息子として会話する」
   - 後：「親子として自然に会話する（呼びかけは不要）」
2. ✅ 明示的な禁止ルールを追加
   - 「『息子！』も付けない。呼びかけは不要」

**検証結果**：
- 以降の応答で「息子！」が出現しなくなった
- 自然な親子会話が実現

#### 4.1.4 ナッジシステムの重複排除

**問題**：
```
会話1回目:
  あなた> 「わかった、頑張ってみる」
  お母さん> 「そういえば、2026-01-28 『最終面接』があるね」
  
会話2回目:
  あなた> 「わかった、準備頑張ります」
  お母さん> 「そういえば、2026-01-28 『最終面接』があるね」（← 重複！）
```

**根本原因分析**：
- ナッジシステムが予定選出時に、前回提案した予定を記憶していない

**実施改善**：
1. ✅ セッション変数 `nudged_schedules` を追加
2. ✅ ナッジ実行時に予定を記録
3. ✅ 次回ナッジ時に除外リストをチェック

**実装コード**：
```python
# セッション初期化
session['nudged_schedules'] = []

# ナッジシステム (Phase 2.5)
if should_nudge:
    available_schedules = [
        s for s in registered_schedules
        if s not in session['nudged_schedules']  # 除外チェック
    ]
    if available_schedules:
        selected = available_schedules[0]
        session['nudged_schedules'].append(selected)  # 記録
        nudge_message = f"...{selected}..."
```

**検証結果**：
- 同じセッション内で同じ予定が2回提案されることがなくなった

#### 4.1.5 注釈アーティファクトの除去

**問題**：
```
お母さん> 「心配そうに: 大丈夫？何があったの？」
          （→"心配そうに:"という感情注釈が含まれている）
```

**根本原因分析**：
- LLMが内部的な「感情マーカー」を生成し、それが出力に含まれている

**実施改善**：
1. ✅ ポストフィルター関数 `_strip_annotations()` を実装
2. ✅ すべてのLLM応答にフィルターを適用
3. ✅ Regex パターンで複数の注釈タイプに対応

**実装パターン**：
```python
def _strip_annotations(text):
    # パターン1：感情注釈 "心配そうに: ..."
    text = re.sub(r'^[^:：]+[：:]\s*', '', text)
    
    # パターン2：括弧注釈 "(共感)", "(会話を終わらせず)"
    text = re.sub(r'[（\(][^）\)]*[）\)]', '', text)
    
    return text.strip()
```

**検証結果**：
- 注釈アーティファクトが出力から完全に除去
- ユーザー体験が自然になった

## 7. 技術的課題と解決策

### 7.1 解決した課題

#### 課題1：LLMの文脈管理

**問題**：LLMが会話履歴から不適切な話題を引き出す

- チェッカーの再生成要求が5%→12%に増加（検出精度向上の証）

#### 課題2：リアルタイムの品質検証

**問題**：すべての応答を手動で確認できない

**解決策**：
- 3層チェッカーシステム
- 自動再生成フロー
- タイムアウト機構（応答なし時の処理）

**効果**：
- 品質問題の自動検出・修正
- ユーザーには品質が保証された応答のみ表示

#### 課題3：セッション管理

**問題**：ナッジの重複、プロフィール情報の一貫性維持

**解決策**：
- Flask-Session によるサーバー側セッション
- ナッジ履歴のセッション追跡
- プロフィール情報のキャッシング

**効果**：
- 複数ターンでの一貫性確保
- ナッジの重複排除
