  "LOGS_DIR": "logs",
  "RECENT_HISTORY_FOR_CHECKER": 10,

  "CHECKER_MODEL": "elyza-mom",
  "CHECKER_TIMEOUT_SEC": 8,
  "CHECKER_MAX_REGEN": 1,
  "CHECKER_LOG_PATH": "logs/checker_events.log",

### 3.2 設定項目詳細

| パラメータ | 型 | デフォルト | 説明 |
|-----------|-----|----------|------|
| OLLAMA_URL | string | http://127.0.0.1:11434/api/generate | Ollama APIエンドポイント |
| GENERATED_MODEL_NAME | string | elyza-mom | カスタムモデル名 |
| RECENT_HISTORY_FOR_LLM | int | 30 | LLMに渡す会話履歴の最大件数 |
| MIN_SCHEDULE_CONFIDENCE | float | 0.7 | 予定関連の安全指示を付与する信頼度閾値 |
| CLASSIFIER_CONFIDENCE_THRESHOLD | float | 0.8 | ルールベース処理に移行する信頼度閾値 |
| CLASSIFIER_MODEL_NAME | string | elyza-mom | 分類器で使用するモデル |
| CLASSIFIER_TIMEOUT | float | 10.0 | 分類器LLM呼び出しタイムアウト（秒） |
| LOGS_DIR | string | logs | ログ保存ディレクトリ |
| RECENT_HISTORY_FOR_CHECKER | int | 10 | チェッカーに渡す会話履歴の最大件数 |
| ENABLE_RESPONSE_CHECKER | bool | true | 応答チェッカーの有効/無効 |
| CHECKER_MODEL | string | elyza-mom | チェッカーで使用するモデル |
| CHECKER_TIMEOUT_SEC | int | 8 | チェッカーLLM呼び出しタイムアウト（秒） |
| CHECKER_MAX_REGEN | int | 1 | 最大再生成回数 |
| CHECKER_LOG_PATH | string | logs/checker_events.log | チェッカーログパス |
| ENABLE_END_DETECTOR | bool | true | 終了検出器の有効/無効 |
| END_DETECTOR_TIMEOUT_SEC | int | 4 | 終了検出器タイムアウト（秒） |
| END_DETECTOR_CONFIDENCE | float | 0.85 | 終了判定の信頼度閾値 |
| END_DETECTOR_LOG_PATH | string | logs/end_detector_events.log | 終了検出ログパス |

### 3.3 環境変数オーバーライド
すべての設定項目は、同名の環境変数で上書き可能。

```bash

export ENABLE_RESPONSE_CHECKER=false
```

## 5. API仕様

### 5.1 チャットAPI

#### エンドポイント
```
POST /api/chat
```

#### リクエスト
```json
{
  "message": "今日の予定は？",
  "use_llm": true
}
```

| パラメータ | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| message | string | ○ | ユーザーメッセージ |
| use_llm | bool | - | LLM分類器を使用するか（デフォルト: 環境変数依存） |

#### レスポンス
```json
{
  "ok": true,
  "reply": "今日の予定はこれね。\n・12:00 NRI"
}
```

| フィールド | 型 | 説明 |
|-----------|-----|------|
| ok | bool | 成功/失敗 |
| reply | string | お母さんの応答 |
| error | string | エラー時のメッセージ（ok=false時） |

#### 処理フロー

```
1. リクエスト受信
   ↓
2. ユーザーメッセージをセッション履歴に追加
   ↓
3. スケジュール意図分類（classifier.py）
   ├─ schedule_query + 高信頼度 → ルールベース処理へ
   └─ それ以外 → LLM処理へ
   ↓
4a. ルールベース処理
   └─ 日付範囲計算 → 予定フィルタリング → 応答生成
   ↓
4b. LLM処理
   ├─ 会話履歴構築
   ├─ フォーカス指示付与（最新メッセージへの応答を明示）
   ├─ LLM呼び出し
   ├─ 応答チェック（ENABLE_RESPONSE_CHECKER=true時）
   │   └─ 問題あり → 再生成（最大1回）
   ├─ ポストフィルター（注釈除去、スケジュール案内除去）
   └─ 終了検出（ENABLE_END_DETECTOR=true時）
       └─ 終了判定 → 予定ナッジ追加
   ↓
5. 応答をセッション履歴に追加
   ↓
6. ログ出力（classifier_events.log）
   ↓
7. レスポンス返却
```

## 6. モジュール仕様

### 6.1 スケジュール意図分類器（classifier.py）

#### 機能概要
ユーザーの発言が予定に関する問い合わせかどうかを判定する。

#### 主要関数

##### classify_schedule_intent()
```python
def classify_schedule_intent(
    user_message: str,
    session_meta: dict = None,
    use_llm: bool = True
) -> dict
```

| 引数 | 型 | 説明 |
|------|-----|------|
| user_message | str | ユーザーメッセージ |
| session_meta | dict | セッションメタ情報（has_schedules等） |
| use_llm | bool | LLM判定を使用するか |

| 戻り値キー | 型 | 説明 |
|-----------|-----|------|
| intent | str | "schedule_query" または "not_schedule" |
| scope | str | "today"/"tomorrow"/"week"/"month"/"next"/"upcoming"/"unspecified" |
| confidence | float | 0.0-1.0 |
| reasoning | str | 判定理由 |

##### _quick_filter()
```python
def _quick_filter(text: str) -> dict | None
```
正規表現ベースの高速フィルター。確実な予定問い合わせパターンを検出。

**検出パターン例:**
- 時間キーワード + 疑問形：`今日の予定は？`
- 確認表現：`予定なにあったっけ`
- 否定パターン：`予定が立て込んでる`（not_schedule判定）

##### compute_date_range()
```python
def compute_date_range(scope: str) -> tuple[str, str] | None
```
スコープから日付範囲を計算。

| スコープ | 開始日 | 終了日 |
|---------|-------|-------|
| today | 今日 | 今日 |
| tomorrow | 明日 | 明日 |
| week | 今日 | 7日後 |
| month | 今月1日 | 今月末日 |

### 6.2 応答品質チェッカー（response_checker.py）

#### 機能概要
LLM応答の品質を検証し、問題があれば再生成を指示する。

#### 主要関数

##### check_response()
```python
def check_response(
    context_messages: list,
    user_profile: dict,
    user_message: str,
    candidate_reply: str
) -> dict
```

| 戻り値キー | 型 | 説明 |
|-----------|-----|------|
| verdict | str | "accept" または "reject" |
| confidence | float | 0.0-1.0 |
| issues | list | 検出された問題のリスト |
| suggested_fix | str | 修正提案（再生成時に使用） |
| action | str | "accept" または "regenerate_with_amendment" |

#### 検証ルール
1. **直接性**: 応答がユーザーの最新発言に直接応答しているか
2. **文脈整合性**: 会話の流れに沿っているか
3. **トーン**: 母親らしい口調を維持しているか
4. **繰り返し**: 同じ質問や確認を繰り返していないか
5. **敬語切替**: 唐突な敬語切替がないか
6. **不適切表現**: 攻撃的・個人情報などが含まれていないか

### 6.3 会話終了検出器（conversation_end_detector.py）

#### 機能概要
ユーザーが会話を終わらせようとしているかを検出する。

#### 主要関数

##### detect_conversation_end()
```python
def detect_conversation_end(
    context_messages: list,
    user_message: str
) -> dict
```

| 戻り値キー | 型 | 説明 |
|-----------|-----|------|
| ending | bool | 終了意図の有無 |
| confidence | float | 0.0-1.0 |
| reason | str | 判定理由 |

#### 検出パターン

**終了シグナル（ending=true）:**
- 別れ表現：さようなら、またね、じゃあね、バイバイ
- 感謝で締める：ありがとうね（単独）
- 短い同意/決意：うん、わかった、がんばる、頑張ります
- 疲労表現：疲れた、もう無理、おわり

**継続シグナル（ending=false）:**
- 質問形式
- 新しい話題の提示
- 悩みの報告
- 相談欲求

### 6.4 プロンプトビルダー（prompts/builder.py）

#### 機能概要
ユーザー設定からシステムプロンプトを動的に生成する。

#### 主要関数

##### build_prompt()
```python
def build_prompt(config: dict) -> str
```

#### テンプレート変数

| 変数 | 説明 |
|------|------|
| {{NICKNAME}} | ユーザーのニックネーム |
| {{DIALECT_LINE}} | 方言設定に基づく話し方指示 |

| {{TOPIC_LINE}} | 関心事項に基づく話題指示 |
| {{LIFE_LINE}} | 生活リズムに基づく配慮指示 |

## 8. エラー処理仕様

### 8.1 LLM呼び出しエラー

| エラー種別 | 対処 | ユーザーへの表示 |
|-----------|------|----------------|
| タイムアウト（120秒） | ログ出力、エラーレスポンス | 「ごめん、回答に時間がかかってしまったわ。もう一度聞いてみてくれる？」 |
| 接続エラー | ログ出力、エラーレスポンス | 「ごめん、接続がうまくいかないみたい。ollamaが起動しているか確認してみて。」 |

### 8.2 チェッカーエラー

| エラー種別 | 対処 |
|-----------|------|
| タイムアウト（8秒） | accept扱いで続行 |
| JSON解析失敗 | accept扱いで続行 |
| その他エラー | accept扱いで続行 |

### 8.3 終了検出エラー

| エラー種別 | 対処 |
|-----------|------|
| タイムアウト（4秒） | ending=false扱いで続行 |
| JSON解析失敗 | ending=false扱いで続行 |

## 9. ポストフィルター仕様

### 9.1 スケジュール案内除去

予定問い合わせ以外の文脈で、以下のフレーズを除去：
- 「予定の詳細については予定管理画面を確認してください」
- 「予定管理画面を確認してみて」
- 「予定管理画面を見て」
- 「予定管理画面で確認してね」

### 9.2 注釈除去

LLM出力から以下を除去：
- 行頭の感情マーカー：`心配そうに:` `優しく:`
- 括弧付き注釈：`（共感）` `（会話を終わらせず）`

**正規表現:**
```python
# 感情マーカー除去
re.sub(r'^[^:：]+[：:]\s*', '', text, flags=re.MULTILINE)
# 括弧注釈除去
re.sub(r'[（\(][^）\)]*[）\)]', '', text)
```

## 10. 予定ナッジ仕様

### 10.1 トリガー条件
1. 会話終了が検出される（ending=true, confidence >= 0.85）
2. 登録済み予定が存在する

### 10.2 ナッジ内容選択ロジック
1. 既にナッジ済みの予定を除外
2. 残りの予定を日時順でソート
3. 最初の予定を選択
4. 選択した予定を「nudged_schedules」セッション変数に追加

### 10.3 ナッジフォーマット
```
そういえば、{date} {time} に『{content}』があるはずよね。準備は大丈夫？
```

### 10.4 フォールバック
登録済み予定がない場合：
```
そういえば、最近どんなこと頑張ってる？いつでも応援してるからね。
```
